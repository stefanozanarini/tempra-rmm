Per-command MFA

Every command is approved by a person, then verified twice more

1

Operator reviews

PCs, module, parameters and validity fixed in one hash.

2

Fresh MFA sign-in

Entra ID nonce = that hash: bound to this command only.

3

Signer verifies

Token, MFA, role, freshness, single use. Trusts no console.

4

Signed job

Ed25519 over tenant, agent, module hash, nonce, expiry.

5

Agent verifies

Signature, addressee, expiry, replay cache, then runs.

Bulk approval

Admins only: up to 500 PCs per approval, one signed job each.

Session approval

Shell, screen and files: one MFA per timed session.

Collections

Read-only inventory and scans need no new sign-in.

Tempra RMM7
The signer is a separate container reachable only by a local socket. It signs only if the request carries an id_token issued by Entra ID for that exact request, recent, with MFA, by an Operator or Admin of that tenant, never used before. The console cannot mint commands by itself. Then the agent checks signature, that the job is addressed to it, the validity window, a persistent anti-replay cache and the module manifest hash.
